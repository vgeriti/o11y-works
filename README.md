## 👋 Welcome & Mission

Observability across enterprise data pipelines, APM, and cloud infrastructure can be complex and intimidating.

**o11y.works** exists to bridge the gap between telemetry specifications and real-world engineering execution—without commercial vendor sales pitches or paywalls. While the web platform itself is managed by the `o11y.works` team, all tools, architecture blueprints, learning paths, and operational guides hosted on the platform are **100% open and free to use** for any engineer or organization worldwide.

## 🔄 The Observability Telemetry Lifecycle

`o11y.works` structures all knowledge guides, architecture blueprints, and developer utilities across the universal 5-stage telemetry lifecycle:

```
+---------------------------------------------------------------------------------------------------+
|                            THE TELEMETRY LIFECYCLE FRAMEWORK                                      |
+---------------------------------------------------------------------------------------------------+
|  1. INSTRUMENTATION & GENERATION  --> Emitting logs, metrics, traces, & profiling data          |
|  2. COLLECTION & TRANSPORT        --> Edge agents, collectors, & buffering pipelines            |
|  3. PROCESSING & PIPELINE ROUTING --> Transforming, enriching, masking PII, & routing streams    |
|  4. STORAGE & RETENTION           --> Indexing data, TSDB cardinality, & cost-effective tiering|
|  5. USE CASE EXECUTION & VALUE    --> Powering APM, SIEM security, triage runbooks, & FinOps    |
+---------------------------------------------------------------------------------------------------+
```

1. 🟢 **Instrumentation & Generation**: Emitting logs, metrics, traces, and profiling data from application code, microservices, and kernel probes.
2. ⚡ **Collection & Transport**: Gathering telemetry efficiently at the edge using lightweight agents, collectors, and buffering pipelines.
3. 🔄 **Processing & Pipeline Routing**: Transforming, enriching, masking PII, reducing data volume, and dynamically routing telemetry streams.
4. 💾 **Storage & Retention**: Indexing data efficiently, managing TSDB cardinality, and configuring cost-effective storage tiering.
5. 🎯 **Use Case Execution & Value**: Turning telemetry into actionable outcomes—powering APM, SIEM security, incident triage playbooks, and FinOps cost control.

## 🛠️ Upcoming Developer Web Utilities & Open Packs

`o11y.works` is built for high performance, zero-tracking, and instant execution. All upcoming developer utilities, configuration builders, and open packs run directly on **[o11y.works](https://o11y.works)** with zero local installation required:

* 📊 **Splunk Apps, TAs & Configuration Builders**: Open Splunk monitoring apps, Technology Add-on (TA) configurations (`props.conf` / `transforms.conf`), and SPL query optimization helpers.
* ⚡ **CRIBL Stream & Edge Pipelines**: Pre-built pipeline configurations, data reduction packs, PII masking rules, and route design patterns.
* ⚙️ **OpenTelemetry Collector Config Builder**: Visual form to assemble valid `otel-collector-config.yaml` files with tail-sampling & batch processors.
* 💰 **Metric Cardinality & Telemetry FinOps Calculator**: Interactive tools to estimate TSDB memory footprints, log ingest volumes, and cloud storage budgets.
* 🧪 **1-Click Local Sandboxes**: Pre-configured Docker Compose lab environments to test OpenTelemetry, Splunk, Cribl, and Prometheus telemetry stacks locally.
