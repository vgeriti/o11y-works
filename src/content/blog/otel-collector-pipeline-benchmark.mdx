## Overview

When operating OpenTelemetry Collectors at high throughput (> 50,000 trace spans/sec), improper processor sequencing or unconstrained memory allocation causes garbage collection thrashing and pod out-of-memory (OOM) kills.

This benchmark guide breaks down the exact processor ordering and tuning parameters to guarantee zero span drops and predictable resource bounds.

---

## ⚡ Recommended Processor Pipeline Sequence

The order of processors inside `otel-collector.yaml` is critical. Always place `memory_limiter` first:

```yaml
# otel-collector-config.yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  memory_limiter:
    check_interval: 1s
    limit_percentage: 80
    spike_limit_percentage: 20

  batch:
    send_batch_size: 8192
    timeout: 1s
    send_batch_max_size: 10240

exporters:
  otlp/tempo:
    endpoint: tempo.o11y.internal:4317
    tls:
      insecure: true

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [otlp/tempo]
```
